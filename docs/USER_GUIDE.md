# PocketVideo User Guide / คู่มือการใช้งาน PocketVideo

## 1. การเริ่มต้นใช้งานอย่างรวดเร็ว (Quick Start in 5 Seconds)
1. **เพิ่มไฟล์วิดีโอ (Add Videos)**: ลากและวางไฟล์วิดีโอจากมือถือ Android (`.mp4`, `.mov`, `.mkv`, `.avi`, `.webm`) ลงในกรอบด้านบน หรือกดปุ่ม **เพิ่มไฟล์วิดีโอ (Add Files)** / **เพิ่มทั้งโฟลเดอร์ (Add Folder)**
2. **เลือกโหมดการบีบอัด (Choose a Preset)**:
   - **เน้นภาพสวย (Best Picture Quality)**: เหมาะสำหรับคลิปสำคัญที่ต้องการเก็บรายละเอียดภาพสูงสุด
   - **คุ้มสุด (Best Balance — ค่าเริ่มต้น)**: แนะนำสำหรับวิดีโอจากมือถือ Android ลดขนาดไฟล์ได้ดีมากโดยที่ภาพยังคมชัดด้วย H.265/HEVC
   - **ประหยัดพื้นที่สุด (Maximum Space Saving)**: เน้นลดขนาดไฟล์ให้เล็กที่สุดเพื่อประหยัดพื้นที่จัดเก็บ
   - **เร็วสุด (Fastest Compression)**: ใช้ GPU Hardware Acceleration (NVIDIA NVENC / Intel QSV / AMD AMF) เมื่อการ์ดจอรองรับ หรือใช้โหมด CPU ความเร็วสูง
   - **กำหนดขนาดเอง (Custom Target File Size)**: ระบุขนาดไฟล์ปลายทางเป็น MB หรือ GB (เช่น บีบอัดวิดีโอ 1 GB ให้เหลือประมาณ 250 MB) ด้วยการเข้ารหัสแบบ 2-Pass แท้
3. **กดปุ่ม "เริ่มบีบอัดวิดีโอ" (Start Compression)**: ไฟล์ที่บีบอัดเสร็จแล้วจะถูกบันทึกไว้ในโฟลเดอร์ปลายทางแยกต่างหาก โดยไม่เขียนทับหรือลบไฟล์ต้นฉบับเด็ดขาด

## 2. การเปรียบเทียบภาพก่อน/หลัง (Before/After Visual Frame Inspection)
- กดปุ่ม **เปรียบเทียบภาพก่อน/หลัง & ทดลองบีบอัดสั้นๆ (Before/After Frame Compare & Sample Preview)** เพื่อตัดตัวอย่างวิดีโอสั้นๆ (2.5 วินาที) มาบีบอัดจริงและแสดงภาพเฟรมเปรียบเทียบแบบคู่ขนานก่อนตัดสินใจบีบอัดไฟล์ขนาดใหญ่

## 3. การแปลงนามสกุลไฟล์และ Smart Remux (Format Conversion)
- ในหน้า **แปลงนามสกุลไฟล์ (Convert Format)** คุณสามารถเปลี่ยนคอนเทนเนอร์เป็น `MP4`, `MKV`, `MOV`, `WebM`, หรือ `AVI`
- **Smart Remux**: หากโค้ดเดกวิดีโอและเสียงเดิมรองรับคอนเทนเนอร์ปลายทาง (เช่น ย้าย H.264/AAC จาก `.mov` หรือ `.mp4` ไปยัง `.mkv`) โปรแกรมจะสลับคอนเทนเนอร์ทันทีโดยไม่บีบอัดซ้ำ (ไม่เสียคุณภาพ 100% และเสร็จภายในไม่กี่วินาที)
- **Full Transcoding**: หากคอนเทนเนอร์ปลายทางต้องการโค้ดเดกใหม่ (เช่น แปลง `.mp4` เป็น `.webm` ที่ใช้ VP9/Opus) โปรแกรมจะแจ้งให้ทราบชัดเจนว่าเป็นการเข้ารหัสใหม่ทั้งไฟล์

## 4. การควบคุมการใช้พลังงานเครื่อง (Resource Management)
- **เบา (Light)**: จำกัดการใช้ CPU สูงสุดที่ 40% (Hard Cap) และตั้งค่า Process Priority เป็น `Idle` เพื่อให้คุณใช้งานโปรแกรมอื่นได้อย่างลื่นไหล
- **สมดุล (Balanced)**: จำกัดการใช้ CPU สูงสุดที่ 75% (Hard Cap) และใช้เธรดครึ่งหนึ่งของระบบ
- **เต็มกำลัง (Maximum)**: ใช้ประสิทธิภาพเครื่องเต็ม 100% เพื่อให้งานเสร็จเร็วที่สุด
- **หมายเหตุทางเทคนิค**: การจำกัดเปอร์เซ็นต์ CPU บน Windows ทำงานผ่าน **Windows Job Object (`JOBOBJECT_CPU_RATE_CONTROL_INFORMATION`)** ซึ่งเป็น Hard Limit ระดับเคอร์เนลที่มีผลกับโปรเซส `ffmpeg.exe` โดยตรง ส่วนการตั้งค่าเธรด, CPU Affinity และ GPU เป็นการควบคุมแบบ Best-Effort

## 5. ภาพนิ่ง + วิดีโอในคิวเดียว (Mixed Media / Image Export)
1. ลากโฟลเดอร์จากมือถือหรือ HDD เข้ามาได้ทั้งรูปและวิดีโอ (รวมโฟลเดอร์ย่อย)
2. คลิกตัวอย่างเพื่อเปิดไฟล์ด้วยโปรแกรมในเครื่อง หรือกด **เอาออก** เพื่อลบออกจากรายการเท่านั้น ไฟล์บนดิสก์ไม่ถูกลบ
3. เลือก **โหมดบีบอัดวิดีโอ** จากตาราง/การ์ดเดิม และเลือก **รูปภาพ → รูปแบบไฟล์ / โหมดบีบอัดรูป** แยกต่างหาก
4. รูปภาพรองรับ JPEG, PNG, WebP, AVIF และ HEIC/HEIF หากตัวเข้ารหัสรองรับจริง โดยใช้ Pillow + libheif; ไม่ใช่เพียงการเปลี่ยนนามสกุล
5. งานรูปภาพกับวิดีโอจะปรากฏในคิวเดียวกัน คลิก **เปิดไฟล์ / เปิดโฟลเดอร์ / เทียบภาพ** ได้เมื่อสำเร็จ

## 6. Suffix และตัวเลือกการเขียนทับ (Output Protection)
- **Suffix:** ใส่ข้อความท้ายชื่อไฟล์ เช่น `_small` จะได้ `IMG123_small.webp` รองรับชื่อไฟล์ภาษาไทย แต่ห้ามใช้ `/ \\ : * ? < > |` และอักขระที่ Windows ไม่รองรับ
- **เก็บทั้งสองไฟล์:** ค่าเริ่มต้นปลอดภัยที่สุด ถ้าชื่อซ้ำให้ต่อเลข 1, 2, 3
- **ข้าม:** ไม่เข้าคิวไฟล์ที่มีชื่อปลายทางอยู่แล้ว
- **แทนที่ไฟล์ปลายทาง:** สำรองปลายทางเก่าก่อน แล้วแทนด้วยไฟล์ที่ผ่านการตรวจสอบ
- **เขียนทับต้นฉบับ:** ต้องเลือกด้วยตัวเอง ยืนยันอีกครั้ง และต้องรักษานามสกุล/รูปแบบเดิม หลัง Export สำเร็จไฟล์เก่าจะอยู่ในรูปแบบ `.pocketvideo_backup_*`
- **ข้อควรระวัง:** เมื่อเลือกทับต้นฉบับหรือปลายทาง ควรมีพื้นที่ว่างพอสำหรับไฟล์ใหม่และ Backup จนกว่าจะตรวจว่าไฟล์ใหม่สมบูรณ์

## 7. Sleep / Shutdown หลัง Export
- **ไม่ทำอะไร (ค่าเริ่มต้น)**, **Sleep**, **ปิดเครื่อง**
- ยืนยันตอนเริ่มงาน และมีหน้าต่างนับถอยหลัง 30 วินาทีให้ยกเลิกเมื่อทุกงานสำเร็จและตรวจไฟล์ผ่าน
- ถ้ามีงานล้มเหลว ยกเลิก หรือไดรฟ์หลุด โปรแกรมจะไม่สั่งปิด/พักเครื่อง
- โปรแกรมไม่บังคับปิดแอปอื่นที่ยังมีงานค้าง และฟีเจอร์นี้ใช้ได้เฉพาะ Windows

## 8. USB / HDD หลุดระหว่างงาน
- โปรแกรมพยายามตรวจไฟล์ต้นฉบับและปลายทางก่อนและหลังเข้ารหัส รวมทั้งตรวจความเปลี่ยนแปลงของต้นฉบับ
- เมื่อพบว่าไดรฟ์ไม่พร้อม งานจะล้มเหลวพร้อมข้อความสาเหตุและหยุดเริ่มงานใหม่ ไม่ดำเนินการเขียนทับต้นฉบับ
- เสียบ HDD/USB กลับเข้าไดรฟ์เดิม ตรวจว่าไฟล์ยังเหมือนเดิม แล้วกด **ลองใหม่** หากข้อมูลบนไดรฟ์เปลี่ยนแปลง ให้ล้างรายการและนำเข้าใหม่
- ถ้าถอดไดรฟ์ระหว่างการเปลี่ยนชื่อไฟล์หลัง Export ให้ตรวจ `.pocketvideo_backup_*` ก่อนจัดการเอง ห้ามลบ Backup จนกว่าจะมั่นใจว่าไฟล์ใหม่สมบูรณ์
- โปรแกรมไม่สามารถรับประกันการกู้คืนจากความเสียหายของระบบไฟล์หรือการถอด HDD โดยไม่ Eject ได้ 100%

## 9. English Summary
Mixed media: import photos and videos in one folder/queue and configure separate video/image profiles. Suffix and collision policy default to **Keep Both**. Explicit replace-original/output keeps backups; never manually delete your backups until you verify outputs. If external storage disconnects, reconnect and retry. Optional sleep/shutdown requires two confirmations and runs only after every verified job succeeded. CPU hard caps apply to FFmpeg subprocesses; Pillow image conversion runs in the app process.


## v1.2.0: Reliability & Quality
- งานที่ค้างก่อนปิดโปรแกรมจะถูกบันทึกไว้ และเมื่อเปิดใหม่จะอยู่ในสถานะหยุดชั่วคราว/ล้มเหลว ต้องกด **Retry Failed** เองหลังตรวจสอบไดรฟ์ USB/HDD แล้ว
- เปิด **Skip larger outputs** ในการตั้งค่า Export เพิ่มเติมเพื่อไม่บันทึกผลบีบอัดที่ใหญ่กว่าต้นฉบับ (ใช้เฉพาะการบีบอัด ไม่ใช่การแปลงไฟล์)
- คลิก **ตรวจคุณภาพ SSIM/VMAF** ในหน้าต่างเล่น Before/After เพื่อตรวจบางช่วงของวิดีโอ คะแนนไม่ได้แทนคุณภาพของทั้งไฟล์
- โปรแกรมอ่านข้อมูลไฟล์ขนาดใหญ่ใน Background; งานรูปภาพเข้ารหัสผ่าน Process แยกเพื่อจำกัด CPU ได้
- หลีกเลี่ยงการถอด HDD/USB ระหว่าง Export และควรใช้ **เก็บทั้งสองไฟล์** สำหรับวิดีโอที่สำคัญ


## CPU Hard Cap และ FFmpeg Threads (v1.3.2)
- CPU Hard Cap (Windows): เลือก 10%, 20%, 30% ... 100% หรือ **Custom** แล้วกรอก 10–100% ทีละ 1% ได้ ตั้งค่าแล้วจำข้ามการปิดโปรแกรม
- ตัวเลข Hard Cap คือสัดส่วนการใช้ CPU รวมสำหรับโปรเซสที่ถูกควบคุม ไม่ใช่การเลือกจำนวนคอร์
- FFmpeg Thread Count: `0` แนะนำให้ FFmpeg เลือกเอง; `4` เป็นคำขอให้บางส่วนของ Encoder ใช้ 4 เธรด **ไม่ใช่ 4% CPU** บาง Codec อาจยังมีเธรดภายในเพิ่มเติม
- macOS ไม่มี Windows CPU Hard Cap จึงแสดงเป็นตัวเลือกที่ใช้ไม่ได้; Thread Count เป็น Best-Effort แทน

## ประวัติและสถิติพื้นที่ที่ประหยัดได้ (v1.3.2)
- หน้า History เก็บตัวเลข **ขนาดต้นฉบับ–ผลลัพธ์ ณ วัน Export** แม้ลบไฟล์เก่าหรือถอด HDD แล้วข้อมูลสถิติก็ยังอยู่
- สถิติสะสมแยกใน `savings_stats.json`; รวมทุกงานสำเร็จที่เคยมีบันทึก และไม่หายเมื่อ History เก่าเลื่อนออกจากตาราง
- % รวมคำนวณแบบ **(ผลรวมขนาดต้นฉบับ − ผลรวมขนาดผลลัพธ์) / ผลรวมขนาดต้นฉบับ × 100** ไม่ใช่เอาเปอร์เซ็นต์แต่ละไฟล์มาบวกกัน
- คลิก **คัดลอกสถิติ** เพื่อแชร์ข้อความ หรือ **คัดลอกรูปสำหรับแชร์** เพื่อ Paste ภาพสถิติลงโพสต์
- **หมายเหตุสำคัญ:** ตัวเลขคือผลต่างขนาดไฟล์ ไม่ใช่พื้นที่ว่างจริงหากยังเก็บไฟล์ต้นฉบับไว้; สถิติที่ถูกลบจากประวัติ *ก่อน* ลงรุ่นนี้อาจกู้ไม่ได้

## Update v1.3.3 — สถิติและจัดการต้นฉบับอย่างปลอดภัย
- History เก็บ **สถิติสะสมของงาน Export สำเร็จ** แยกจากรายการประวัติ แม้ลบต้นฉบับหรือกด Clear History ตัวเลขสะสมยังอยู่ แต่งานเก่าที่ไม่เคยถูกบันทึกจะกู้กลับมาเองไม่ได้
- คอลัมน์ **Remaining Size ≈** แสดงขนาดไฟล์หลังบีบอัดเทียบต้นฉบับ เช่น **≈20%** หมายถึงไฟล์ใหม่เหลือประมาณหนึ่งในห้าของไฟล์เดิม
- Maximum Space Saving เปิด **Enable 2-Pass** เพิ่มได้ (ค่าเริ่มต้นปิด) ตั้งเป้า Bitrate วิดีโอประมาณครึ่งหนึ่งของต้นฉบับ ใช้เวลานานขึ้นและไม่รับประกันขนาดไฟล์/คุณภาพ
- Concurrent Jobs เลือก **1–8**; ลดงานพร้อมกันบนเครื่องที่ CPU/RAM จำกัด ทั้งนี้ Windows CPU Hard Cap ต่อโปรเซสไม่ใช่ขีดจำกัด CPU รวมของทุกโปรเซส
- หลัง Export สำเร็จ ใช้ **Move Original to Trash** ต่อไฟล์ หรือ **Move All Originals to Trash** โดยตรวจ Fingerprint ของต้นฉบับ/ผลลัพธ์ และยืนยันก่อนทุกครั้ง ไฟล์จะอยู่ในถังขยะ ต้องล้างถังขยะจึงคืนพื้นที่ว่างจริง
- **Clear Finished Jobs** ล้างงานคิวที่จบแล้ว; **Clear History** ล้างรายการประวัติที่มองเห็น ทั้งสองไม่ลบไฟล์จริงหรือยอดสะสม
- Preserve Metadata พยายามเก็บ Date Created บน Windows และ Modified/Access time บนระบบไฟล์ที่รองรับ หากคัดลอกไม่สำเร็จจะมีคำเตือน
